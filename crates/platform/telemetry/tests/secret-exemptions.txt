# TASK-024 11.5f: reasoned exemptions for secret-shaped struct fields.
#
# Format: class | path-from-workspace-root | struct | field | reason
not-a-secret | apps/cli/src/rotate_credentials.rs | Evidence | credential | static credential-kind label (postgres, redis, etc.), never credential material; report renders only names and booleans
#
# A field appears here only when wrapping it in Redacted<..> / SecretRef is
# impossible or would defeat its purpose; the class names the mechanical
# rule that keeps it safe (enforced by tests/secret_inventory.rs):
#
#   config-carrier      plaintext by necessity at startup; owning struct
#                       derives neither Debug nor Serialize
#   runtime-carrier     process-lifetime holder; derives neither Debug nor
#                       Serialize
#   wire-in             deserialized payload from an external provider; the
#                       struct derives no Serialize (one-way door)
#   wire-out            serialized request body to an external provider;
#                       derives no Debug
#   capability-input    request DTO receiving a capability token from its
#                       owner over TLS; derives no Serialize
#   capability-delivery response DTO handing a one-time capability to its
#                       authenticated owner; derives no Debug
#   manual-redaction    same-file manual Debug (and serde guard) renders a
#                       redaction marker for this field
#   public-by-design    the value is published by design (e.g. a DNS TXT
#                       challenge token) — not a secret
#   ciphertext          encrypted-at-construction material or a one-way
#                       verifier, not plaintext
#   not-a-secret        name collision only (pagination cursor, boolean)
#
# Entries whose class rule their struct violates FAIL the gate; entries that
# match nothing FAIL the gate (no rot). Adding a secret-shaped field without
# wrapping or classifying it here fails the build.
