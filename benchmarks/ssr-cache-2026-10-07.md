# SSR response cache — flag on and measured (TASK-022 step 7, slice 11.3g)

**Lab, not production.** Same posture as
[`../load3x-2026-10-07.md`](../load3x-2026-10-07.md): seed 1 scale data
(`sanvi_scale`), compose Postgres 18 on port 5433, **release build 0.10.0
rebuilt from current main before the run** (11.3a–f included), Redis warm,
rate limiting disabled, tracking abuse quota raised, `features.advertising`
on with dev signing secrets. Machine profile
`{"cores":20,"mem_gb":16,"os":"Windows 11 26200","arch":"x86_64"}`, host
shared with unrelated Docker stacks — including `hdms-staging-*`, which came
up with the Docker daemon restart mid-slice and was running for every rc.4+
run but not for rc.3 (recorded; the same-binary A/B below is what makes the
comparison honest).

The single delta from the TASK-021 posture: **`platform.ssr_cache` ON**
(`SANVI__SERVER__SSR_CACHE__ENABLED=true`, launch script
[`lab-api.sh`](lab-api.sh), committed).

## What the flag turned on

The keyed cache of 11.3c over the storefront **content reads** (locales,
messages, plans, privacy disclosures): GET/HEAD on `/api/v1/public/`, keyed
by `(tenant, locale, theme revision, device class, route)` (11.3b),
single-flight on miss, event-driven invalidation within ~2 s on theme
publish / content change (11.3d), counters registered once per process.
Authenticated requests are never served from or written to the cache;
`Set-Cookie` responses are never stored; `no-store`/`private` always
refuse; `no-cache` with a strong `ETag` is storable because revalidation is
structural (the revision is in the key) and the replayed headers keep
downstream caches revalidating.

**Deliberately excluded** (11.3g findings, both measured before the final
candidate):

- `/api/v1/public/theme` — its handler is already cache-first (the
  resolved-theme cache + single-flight of TASK-021 11.2g), so a hit re-pays
  the key build's two resolution reads (host→tenant, tenant→theme revision)
  to skip a handler that no longer renders anything.
- `/api/v1/public/tenant-context`, `/api/v1/public/slug-availability` — a
  cached availability/context answer outlives the status it reported; the
  SSR invalidation events never fire on tenant lifecycle changes.

## Two defects fixed on the way to a truthful measurement

1. **Shared metric-family collision.** The first wiring reused
   `CacheMetrics` (`cache_hits_total`), whose family the access context
   already registers — the duplicate registration failed silently
   (`AlreadyReg`, error swallowed) and every increment was orphaned:
   `/metrics` showed `hits 0` while Redis held warm entries. Fix: a
   dedicated family (`ssr_cache_hits_total` / `ssr_cache_misses_total` /
   `ssr_cache_joins_total`).
2. **Counters invisible under 20 workers.** `build_app` runs once per
   actix worker; per-worker registration left 19 of 20 workers incrementing
   unregistered clones. Fix: the `SsrCache` (and its metrics) is built once
   in the binary's main and passed into `build_app`; the shared Arc also
   makes the single-flight map genuinely process-wide.

Plus one **pre-existing test defect the verification run exposed**: the
advertising budget tests seeded metrics rows at the UTC date while the
budget windows query the tenant-calendar (JST) date — red for ~9 h/day
(15:00–24:00 UTC). TASK-021's close had run inside the green window; fixed
in `30b4d47` (test-only).

## The A/B that decided the theme exclusion

Same binary, same host, same co-tenants, five runs of `storefront_read`
(the k6 shape = tenant-context + public theme; every iteration a fresh
connection, so workers round-robin):

| run | flag | p50 ms | p95 ms | p99 ms |
|---|---|---:|---:|---:|
| rc.3 (pre-TASK-022 binary) | n/a | 3.40 | 5.52 | 7.98 |
| rc.4 / rc.4b / rc.4c | on (theme cached) | 4.12 / 4.19 / 4.52 | 5.92 / 6.55 / 6.13 | 9.88 / 13.42 / 8.77 |
| rc.4-off / rc.4-off2 (same binary as rc.4) | **off** | **3.87 / 3.67** | 5.54 / 5.32 | 8.51 / 7.36 |

The ~+0.5–0.8 ms p50 is the flag's real price on a path that cannot
benefit; rc.4b/c's p99 spread (8.8–13.4 between same-binary runs) shows the
tail noise floor of this shared host. Excluding `/theme` removes the cost.

`conversion_upload`'s rc.4 p99 flag (18.4 ms vs rc.3's 7.0) was tail noise:
two same-binary repeats measured 4.7 and 6.0 ms, at or below the baseline.

## Final candidate: rc.6 — all five shapes OK against rc.3

Five k6 shapes, 60 s each at the offered rates, tag `rc.6`
(`benchmarks/<scenario>/rc.6.json`, stats_version 2), all 0 failed /
0 dropped, `scripts/perf-compare.sh rc.3 rc.6` **exit 0**:

| shape | offered | p50 ms (rc.3 → rc.6) | p95 ms | p99 ms | verdict |
|---|---:|---|---|---|---|
| storefront_read | 50 | 3.40 → 3.96 | 5.52 → 5.36 | 7.98 → 7.49 | within tolerance |
| admin_write | 20 | 3.69 → 4.22 | 7.58 → 8.72 | 12.56 → 10.32 | within tolerance |
| checkout_create | 10 | 3.83 → 3.64 | 7.91 → 7.06 | 13.22 → 10.12 | within tolerance |
| webhook_flood | 100 | 1.37 → 1.51 | 3.21 → 3.38 | 4.74 → 4.89 | within tolerance |
| conversion_upload | 50 | 2.51 → 2.71 | 5.27 → 3.93 | 7.01 → 5.43 | within tolerance |

**Where the improvement shows.** Not on these five shapes: they exercise
the bootstrap reads (tenant-context, theme), both excluded, both already
served from the 11.2g caches. The SSR cache's win lands on the DB-bound
content reads the shapes don't cover — the privacy disclosures (four
rebuild-per-request reads in the 11.2c profile) and public plans — and on
database load: every hit is one render the store never sees. The gate
passes with the flag ON because the excluded paths pay nothing; that is the
designed shape, not a waiver.

**Hit-ratio evidence, flag on** (post-rc.6, live lab API): the k6 shapes
generate no SSR traffic (bootstrap excluded) — by design. Probing a cached
read (`GET /api/v1/public/locales`, `scale-tail-1-000.localhost`): 6
requests → `ssr_cache_misses_total 1`, `ssr_cache_hits_total 5`,
`ssr_cache_joins_total 0` — hit ratio 5/6, counters process-wide. During
the rc.5 run (before the tenancy exclusion) the same counters had counted
~2,986 tenant-context hits across the 20 workers — the observation that
surfaced the exclusion above.
